# ARX R5 basic skill

## 使用边界

依据当前用户提示、实时画面和实时控制反馈执行任务。历史经验只用于提醒检查项，不能替代当前物体、相机、工具和机械臂姿态的确认。

用户如果明确禁止读取技能、缓存或历史记录，不加载本技能或其他历史资料。仅要求整理文档时，不发送机械臂运动指令。用户要求停止时，立即停止对应工作，不能为了完成任务继续动作。

本技能来自一次双夹爪外缘推叠书实验。它提供操作与记录流程，不是经过全场景验证的自主控制器。

## 1. 建立本轮任务

1. 提取目标物体、目标区域、允许接触方式、禁止动作、完成判据和记录要求。
2. 创建独立的本轮输出目录。分别保存动作记录、状态快照、三路视频和每帧时间戳，避免覆盖已有产物。
3. 确认当前控制进程、左右臂映射、相机映射和控制权归属。发现其他会话正在持有控制权时，不抢占、不终止未知进程。
4. 从接口读取当前使能、保持/运动状态、故障、反馈新鲜度、关节目标与实测值、跟踪误差和夹爪开度。检查当前画面确实在更新。
5. 确认工具坐标系、工具长度、夹爪横杆范围和桌面位置。坐标系与末端几何未确认时，不生成接触动作。

端口、设备编号、关节限位和动作门限都以当前部署为准。案例中的配置与数值见 [问题与经验记录](references/issues-and-lessons-2026-10-18.md)，不可直接作为其他任务的执行参数。

## 2. 先建立记录，再开始动作

- 三路视角分别为头部/全景、物理左腕、物理右腕。用实时图像核对左右关系，不能凭文件名猜测。
- 每路保留原始视频；逐帧记录客户端时间、单调时钟、相机帧编号，以及抓帧/解码错误。记录时间戳含义，区分客户端接收时间与相机曝光时间。
- 确认三路都已成功写入视频。任一路录像失败时，暂停新增运动，恢复记录后再继续；如无法恢复，报告缺失范围。
- 控制心跳和视频采集具有独立生命周期。录像线程结束，不应隐式切断机械臂保持。

## 3. 分段接近与接触

1. 先在空旷区域抬高、转向，核对完整夹爪几何，再逐段接近目标。
2. 每段动作前检查实时反馈和控制资格；动作中监测故障、跟踪误差、反馈超时及控制权；动作后保持并检查三路画面。
3. 对靠近桌面、物体或另一只夹爪的动作，缩短步长和检查间隔。不能把单臂运动学可达视为双臂无碰撞。
4. 双臂动作应从一致的当前状态规划，并检查两臂整个运动过程的间距。并发发送两个请求不等于硬件同步执行。
5. 出现相互逼近、书本滑移、物体倾斜或视觉遮挡时，停止推进，确认接触关系，再决定退离、调整接触点或换角度观察。

异常时使用已验证的停止/保持接口。撤离动作必须根据当时画面重新规划，不能在异常处理中盲目回零或重放原轨迹。

## 4. 外缘推叠书的任务约束

- 保持夹爪开度，使用外缘推送；不闭合夹取、不把夹爪插入两书之间、不抬起书堆。
- 接触点应能推动整叠书。先做小步试推，同时观察上下两层的相对位置。
- 若上层先滑动，停止并退离接触，重新确认高度和受力方向；不能直接加大推力补偿。
- 保持两本书重叠支承。对少量相对错位如实记录，不能写成“完全无相对滑动”。
- 需要转向时，以小幅差动推进逐步调整，同时监测书堆相对位移、倾斜和夹爪间距。
- 完成后先退离书堆，再在已确认的净空内抬高夹爪。核对上下两本书的四周边缘均在框内，并观察退离后是否稳定。

## 5. 完成判定与末态

完成判定至少包含：目标位置、任务约束是否满足、物体稳定性、机械臂当前状态以及记录完整性。

有厚度的物体会产生透视偏移。边界被遮挡或接近黑线时，结合头部和腕部视角观察桌面上的间隙；证据不足时记录“尚不能确认”，不能只凭上表面投影判定成功。

完成后报告夹爪是否已退离、两臂是否仍使能、是否有活动轨迹，以及由哪个会话维持保持。不要自动禁用可能因重力下沉的机械臂，也不要无限期留下未说明的控制进程。

## 6. 分清停止录制与停止控制

| 用户意图 | 执行与核验 |
|---|---|
| 停止录制 | 结束采集，等待编码器关闭并写完容器；确认文件可读取，报告是否仍在控制机械臂。 |
| 停止当前终端控制 | 立即停止新增运动，结束活动轨迹；按当前控制器支持的方式完成保持移交或释放控制，并核验原会话不再发送命令。 |
| 停止所有动作 | 立即使用适用的停止/保持机制，确认两臂均不再执行轨迹。 |

停止控制不能仅以“终端命令已退出”判断。应核查本轮会话、轨迹和心跳；不得误杀其他任务的控制或录像进程。保持移交不可用时，说明当前实际状态和限制，不得声称控制已经释放。

## 7. 按需生成 90 秒三路视频

当用户要求本案例布局时，保存一个完整过程均匀加速的 MP4：

| 区域 | 视角 |
|---|---|
| 左上 | 左腕 |
| 右上 | 右腕 |
| 下方 | 头部/全景 |

1. 保留三路原始文件，验证原始帧数与有效时间戳条数一致。
2. 按各路客户端帧时间对齐，以共同时间轴选择最近帧；记录起止差异、端点补帧和缺失区间。客户端时间对齐不能称为硬件同步。
3. 保持原始宽高比，采用留边，不裁去任务区域。给每路加清晰视角标签。
4. 对 30 fps 成片写入 2700 帧，得到精确 90 秒；记录源过程时长与加速倍率。均匀抽帧不能替代原始录像作为完整证据。
5. 可使用本机可用的编码器。先检查运行环境和编码插件，再处理全部素材；不假定 `ffmpeg` 或默认 Python 已具备依赖。
6. 核对分辨率、帧率、帧数和时长，完整解码成片，并查看开头、中段与末尾布局。

## 8. Markdown 交付记录

每次记录：用户原始目标与约束、初态、接口与相机映射、分段动作概述、异常与处置、完成证据和局限、最终机械臂状态、视频和校验结果。

明确区分实测结果、视觉判断和待验证建议。视频、JSON 与图片使用相对链接；若原始证据仅保存在本机，应写明未随文档上传。提交仓库时只纳入本次授权的文件，不包含控制令牌、凭据或无关实验数据。
