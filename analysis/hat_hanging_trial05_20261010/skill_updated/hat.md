# L1：左臂把帽子挂到最低挂点

这是 2026-10-03 新增任务，复用共用控制、录像与记录流程。第 1 轮未完成挂放：多次接近仍未证实独立支撑，帽圈接触带动挂架；5 mm 指令回撤未通过到位检查，保护失能后左臂回落、帽子落桌。不是受控回位。后续授权轮次另存初态和参考，不复播第 1 轮轨迹。

## 目标

左臂抓起帽子，挂到木架上高度最低的实际挂点；右臂只辅助观察，不扶架、不抓帽。区分挂衣斜杆与桌面支撑脚，不能把支撑脚当最低挂点。用户已明确本次选择最低挂点，不再询问挂点偏好。

## 操作依据

1. 新图辨认帽檐、帽圈/开口与可夹部位，选择能稳定夹持且不遮挡挂放开口的位置。检查帽子是否仍受桌面或人工预置支撑，不能将预置接触计为自动抓取。只夹帽子，避开架杆、夹爪本体和相机线缆。
2. 分步接近并闭爪，短距离试提。帽子独立离开原支撑、持续随爪且无明显滑移/过度变形后，再取新图确认抓起。帽子柔软、结构与旧任务不同，不沿用抓花或抓笔的夹爪数值。
3. 核对帽子完整外形与架子立柱、支脚、其他挂杆的净空，先抬高/移到无接触空间再运输。需要右侧视角时先让左臂静止，右臂在自身侧调整且不得伸入挂帽通道。
4. 让帽圈/合适开口对准最低挂点的自由端，看到前后间隙后分段接近。沿可见挂杆方向把开口送过端部，使帽子逐渐受挂点支撑；不靠拉动架子、硬压帽檐或在遮挡下穿杆找位置。
5. 帽子受挂点支撑后逐步松爪，确认空爪并沿不会勾带帽子的方向撤离。至少两次相隔数秒的新图确认帽子独立挂在指定最低挂点、未落回桌面、架子稳定才记挂放成功。
6. 左臂空爪受控回本轮参考，右臂若动过也回位；核验后正常封存三路 MP4，记录 prompt、阶段时间、人工介入、失败/重试与公开对话 MD。

架子倾斜或移动、帽子卡在夹爪/杆上、滑落、接触不明或视角不足时停止推进，先重新观察。在支撑和路径明确时才释放/回撤；无证据不能盲拉或扩大动作。若原夹持位置挡住挂放，不在悬空无支撑时直接松爪换抓。

证据汇总：[挂帽三轮记录](/home/tuojing/arx_r5_control/HAT_HANGING_EXPERIMENT_RECORD_20261003.md)。第 2 轮人工预置接触后的夹持/运输和桌面释放通过，挂放未完成；第 3 轮从桌面拾取三次试提均失败，随后双臂受控回位通过。两轮三路 MP4 均已正常封存。尚未验证的阶段不能预填成功。

用户明确要求自主观察，不让用户从旁代判帽圈是否套过挂杆。提前选择能分辨杆端与帽圈前后的观察位；夹持部位和帽圈姿态应给挂入及空爪退出留出通道。当前软件没有已验证的接触力控制。发现架子被带动，应停止推进；最小步长被动作前检查拒绝时不能为通过检查而放大近接触动作。人工复位后若帽子已在夹爪处，记录预置接触/持帽初态，不能记成自主抓取。

第 3 轮提示：侧视差和新的接近姿态仍可能不足以让帽圈进入夹面；三次闭合到位均未带起帽子。应保存试提前后的完整帽子与桌面关系，不把腕图中帽圈恰好落在夹指投影之间当作抓取证据。未形成新空间依据时按共用流程结束尝试，保留失败与受控回位结果。

## 第4轮：人工辅助布置后挂稳（2026-10-07）

本轮从人工搭帽于左爪开始，运行中人工重新摆帽一次、移动并转向木架一次。新位置下左臂分段下放，右腕看到最低杆端进入帽圈；逐步松爪后，单侧夹指仍贴着帽沿，单纯轴向回撤会带动帽子绕挂杆转动。在确认另一侧间隙后，沿张开轴侧移解开接触，再退出夹指，帽子独立挂稳。两次稳定观察相隔5.89秒；左6段、右2段受控回位，两次误差核验通过。

该结果仅验证人工辅助初态下的挂放及收尾，不验证自主取帽或原摆位下自主对准。人工移架后应重判杆端和退出通道，不能把移架产生的对齐记为模型动作。松爪后仍须检查单侧指尖，不能仅凭开度或帽圈套杆宣布独立支撑；侧移方向和幅度须由当前图像间隙决定，禁止照搬本轮坐标。

## 第5轮准备：SDK故障阻止恢复（2026-10-10）

本轮计划从盒上自主取帽。确认上轮碰撞后承托、相机线缆及清场后，左SDK一次初始化收到CAN回包，却报“电机编号2，故障类型12”并退出，尚未完成初态恢复或进入抓取。用户后续说明仅手动复位、尚未断电重启；恢复状态以[第5轮记录](/home/tuojing/arx_r5_control/HAT_HANGING_EXPERIMENT_RECORD_20261010.md)为准。回包、短暂ready事件及故障后留存RX数不能代替持续健康反馈；本例不能按接口缺失直接运行restore_can，也不能当正式挂帽失败。故障码含义尚未核实。

续行时用户已将左臂本体断电再上电。此后两次左SDK初始化均无CAN接收，六关节反馈无效，日志报告全部6个电机掉线；中间仅按受限脚本重启过固定左CAN桥接，右侧未改动。重建后can0累计TX 31,361包、RX 0包，说明接口UP和脚本成功本身不足以恢复通信。当前等待本体到CAN转接器接头/线缆现场检查结果；无新物理条件时不再循环连接。三段三路MP4与资源快照保留，仍未开始挂帽动作。

用户完成现场接线检查后要求再次使用`restore_can.sh`。此时can0仍存在，原脚本会按保护条件拒绝直接执行；受限重启脚本确认左worker已退出和适配器身份后，移除旧桥并调用原`restore_can.sh`成功重建。新图可见道具重新摆位，但左SDK仍零回包、六关节无效，can0累计TX 25,483包、RX 0包；右臂反馈正常。故障左worker已退出，第四段三路录像封存。进一步恢复须有新的物理通信证据，不能把“CAN interface restored”解读为电机已连接。

再次续行时，左CANable因现场插接重新枚举为ttyACM1，旧can0消失；原`restore_can.sh`在适用条件下实际恢复接口。用户确认左臂底座插头已重插、本体上电、工作区清空，新录像覆盖一次左SDK初始化；仍全部6个关节无反馈，can0累计TX 26,894包、RX 0包。现场无备用CAN线或转接器，不能在相同条件下再循环重连；第5轮以恢复阶段设备通信故障封存，未进行正式挂帽。该症状只定位到左侧公共反馈路径，不能单凭零回包判定线、转接器或本体中哪一个损坏。
