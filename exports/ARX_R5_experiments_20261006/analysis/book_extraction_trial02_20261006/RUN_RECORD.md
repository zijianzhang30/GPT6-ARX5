# 中间书本抽取第2轮 — 实验结果

2026-10-06，左臂负责抽书。**本轮未验证抽出成功，双臂已受控回位，两次核验通过。** 改抓书边中段后仍未建立可靠夹持；本轮证据不足以判断机械臂拉力不足，也不能据此断言任务无法完成。

## 目标与分工变化

初始协议v1：右臂尝试抵住上方书，左臂将中间书抽出约5厘米、其他书保持稳定。13:21:04用户明确说“没事 这个不算问题 就把书抽出来一些就行 不用考虑别的了”，因此协议v2允许其他书轻微随动，仅要求目标书相对阶段初态明显抽出一段。随后用户要求改抓书边中段，右臂辅助观察、避免干涉；v2中段阶段右爪没有抵住上书。两个协议分别判定，未把原来的严格稳定要求继续作为v2的失败原因。

冻结目标见 [初始任务](task_prompt.md)、[协议v2](protocol_v2.md)、[改抓中段](mid_edge_reapproach_protocol.md)。三本书平叠在蓝盒上；初始突出的书边、原因未明的整堆移位、后续人工拿书均不算自主抽取量。

v2合计三次独立的12毫米TCP指令试拉（角部一次、中段两次），**不是36毫米书本位移**。没有可靠的实际抽出长度量测，不能记为抽出5厘米或“抽出一些”成功。夹爪开度是控制归一化值，不是毫米或夹持力。

## 失败原因与证据边界

直接问题是夹指没有可靠夹住中间书并带动它：抓点、高度、姿态与夹入深度的组合仍不合适，试拉时未确认书跟随。书堆接触区域有遮挡，既不能确认每次两侧夹指实际接触的位置，也未测得接触力，因而不能把原因直接归为力气不够。改抓中段是实际尝试过的方法，但本轮不支持“中段一定优于角部”的结论。

右臂在v1的可靠承力没有验证；v2改用观察角色。没有观察到双臂接触，本轮没有运行电机故障或失能下落。发生3次动作前新鲜观察拒绝，没有执行相应硬件动作；离线关节余量/会话预算拒绝另列于事件中，不算运行故障。所有原有保护保留。后续若重试，应先核验上下夹指对目标书形成有效夹持，再用短试拉确认书相对固定背景跟随；本归档没有执行新一轮。
