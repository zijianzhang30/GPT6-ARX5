# 健康状态下的受检回位

本入口用于用户要求结束/取消任务时，在仍有新鲜反馈、带电保持且经视觉确认空爪和路径清晰的条件下，分段回到当前控制会话保存的初始关节位。**它不是失能后的回位，也不是防坠装置。** 失联、断电、卡住或执行故障后不会靠本入口自动运动。

## 使用边界

- 保留原心跳、相机、反馈、跟踪、到位、速度、关节余量和预算保护；未替换任何故障停止分支。
- 只有双臂均处于健康静止保持时才能开始，每段只动所选工作臂。保持两爪原指令不变，不自动放开物体，不自动续预算、清故障、使能或断使能。
- 每段需要新鲜且未消费的观察，核对当前实际空爪、整个运动通道和三路录像。布尔字段是调用者的审阅声明，程序不把它们当传感器测出的抓取/碰撞认证，也不从夹爪开度推断空爪。
- 使用既有 `return_plan` 的单段6°/关节、8.25°关节向量上限及原速度；规划仍受当前会话的额外跟踪余量、最小指令步长和预算限制。被拒绝时重新检查，不放宽约束、不自动扩大步长。
- 初始参考从宿主的 `initial_state.json` 对应内存快照复制，之后不能通过该命令改写。它是该宿主的初始位；若跨任务复用宿主，不能冒充另一任务的回位参考。
- 回位完成同时核对实测和指令均在原2.5°容差内，并继续带电保持。没有承诺断电、失能或异常后的承托能力。

## 接口

仅适用于 `tools/held_policy_review.py` 已经运行的普通 `--working-arm left/right` 会话。此命令本身不启动宿主；不适用于单臂交接模式、顺序叠杯阶段或隔离探测模式。请勿为了获得入口而终止健康持物宿主或重新使能故障机械臂。

在当前三路画面确认空爪、人员离场、完整路径清晰，并核对录像manifest后，取最新 `review_packet.json` 中所选臂的 observation_id，再发一条：

```text
reviewed-return-step {"observation_id":"替换为当前观察ID","empty_gripper":true,"path_clear":true,"recording_active":true,"note":"记录本段空爪和完整回位通道的视觉依据"}
```

宿主记录 `reviewed_return_step` 事件，含参考、实测/指令误差、所选臂、执行结果和审阅声明。`at_initial=false` 只表示这一段尚未回到参考；下一段必须重新看图并使用新观察。预算不足需在原健康续段条件下另行处理，不能当成任务已完成。

旧回位接口为兼容既有实验保留；本次新检查只应用于 `reviewed-return-step`，不能据此声称所有历史入口都有相同审阅绑定。

## 验证与限制

`tests/test_reviewed_return.py` 使用模拟硬件验证分段到达、固定参考、只动所选臂、保持夹爪和使能、拒绝过期/重复观察、拒绝未审阅路径/空爪/录像、拒绝状态漂移及故障/失能/失联、保留规划和预算拒绝、执行失败不重试。

宿主测试覆盖新入口分发、事件写入、模式限制和原故障清理。2026-10-05抽屉第2轮已在健康空爪下完成双臂分段回位。62、76、92因审阅后的细小状态漂移在运动前拒绝，重新观察后继续。左臂因宿主初态与任务准备前初态不同，另用原笛卡尔规划器作最终修正；两臂独立核对本轮参考均通过2.5°容差。证据见`analysis/drawer_push_pull_trial02_20261005/review_archive/`和`return_verification.json`。此验证限于健康空爪收尾，不是故障/失能后的恢复验证，也不能代替机械防坠装置。
