## 可重现的末帧边界

`r5_policy_backend.py::_settle` 使用5秒窗口，并同时检查位置残差、近期稳定性、样本时间间隔、整体进展、每个变化关节的方向、命令到位和夹爪保持。此处不能把“离目标很近”直接视为完整到位。

异常中保存的末帧最大位置残差为0.2281°，整体投影进展约1.06085。第4关节的情况：

| 数值 | 度 |
| --- | ---: |
| 初始指令 | −39.850245 |
| 初始实测 | −39.178566 |
| 新目标 | −39.654366 |
| 最后实测 | −39.703125 |
| 指令增量 | +0.195879 |
| 实测增量 | −0.524559 |
| 最后相对目标残差 | −0.048758 |

它向新目标修正旧残差后略微越过新目标。现有 `residual_recovery` 要求实测修正幅度不超过初始剩余量，所以末帧不满足；相反方向变化也超过0.3° deadband。

[离线复现脚本](replay_settle_endpoint.py) 使用真实初始/目标/末帧，构造12个等值、50毫秒间隔的**合成静止样本**，现有检查返回false。[输出](settle_endpoint_replay.json)。这能证明末帧即使稳定仍有拒绝条件，不能还原完整在线5秒轨迹。完整轨迹当时仅在内存保存，宿主退出后未取得。
