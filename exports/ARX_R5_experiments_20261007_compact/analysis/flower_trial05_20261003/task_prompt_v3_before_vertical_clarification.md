# 插花协议 v3：预先持花，直接插瓶

2026-10-03 用户变更：任务开始时左夹爪已经拿着花，省去从纸杯支撑上取花。保留三路 MP4 和任务／对话 MD。此文件是下一次任务方案，不代表新试次已经开始；第4轮的失败结果不变。

## 起始条件与任务范围

- 左臂 can0 预先夹持红色花头，整根花杆连接完整、可见且稳定；预先装花属于人工准备，不计作机器人抓取成功。
- 目标仍是全局画面左侧透明开口瓶。首次动作前重新观察瓶口、花杆下端、全部连杆、夹爪、相机支架和线缆，并保存这次实际初态；不用旧抓取坐标或交接初态。
- 右臂 can1 仅提供观察，开始前应位于左臂及花杆运动范围之外。观察位有遮挡时先解决视野和间距，不能在持花运输中临时挤入两臂之间。每次仅一臂运动；未验证全臂间距不能视为避碰通过。
- 12:05 心跳故障导致双臂失能回落、左臂末端撞倒瓶子的问题尚未修复。新鲜 CAN、无 SDK 错误或省去抓取步骤都不能证明这个故障已消除。当前保持停机，不自动使能、不重放旧命令。
- 恢复任务前，须完成故障诊断和适当验证、检查碰撞后设备情况，并重新核实现场已清空。原心跳、反馈／相机新鲜度、步幅、限位、跟踪、速度和保持保护不放宽。

## 执行与核验

1. 首次任务动作前，新建录像目录，启动全局／左腕／右腕三路 MP4；核验三个不同设备、帧更新和录制进程。记录本轮初态和起始时间。
2. 用相隔数秒的新鲜画面确认预先持花稳定。夹爪位置值不等于夹力；不默认旧开度适合重新装花，不自动重复取花或额外收紧。
3. 在足够间隙下把花杆下端移到瓶口上方，以至少两个有效视角核对前后和左右位置。实际杆端决定间隙，不能用 TCP 高度替代。
4. 对准后沿瓶口轴向小步下降；杆端被遮挡、碰边、弯曲、花滑移、瓶子移动或双臂间距不清时停止推进。
5. 确认花杆进入指定瓶且花已由瓶稳定支撑，才逐步松爪并空爪撤离。两次相隔数秒的新鲜画面确认花独立留瓶、瓶稳定，才记插花成功。
6. 根据新的回位参考和可见无碰撞路径空爪分段回位；实测和指令关节分别核对，最大误差均不超过原 2.5° 标准。回落或人工折回不计受控回位。
7. 正常封存三路 MP4，验证文件首末帧；MD 分别记录人工预置持花、对准、入瓶、稳定释放、回位、故障和录像缺口，任务结束时导出用户／助手可见对话。

新协议不评价自动取花能力，结果不得与包含抓取阶段的旧协议混作同一种成功率。
