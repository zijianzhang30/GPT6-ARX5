# 到位失败后的有条件带电保持

## 原因与适用范围

瓶盖第1轮命令100触发的是关节到位失败，随后原故障路径向两臂发送 stop，实际失能落桌。原始到位判据仍然有效，不能为了避免失能将这次动作改判为成功。

新增 `--retain-settle-fault-hold`，默认关闭，只供 `tools/held_policy_review.py` 的普通 `--working-arm left/right` 模式选择；不与单次诊断或相机故障恢复模式合用。启用该模式仍一次只允许一臂接收目标。新选项不自动启动、重连、使能或认定硬件合格。

只有关节动作的原到位检查超时，才尝试以下路径：

1. 沿用原反馈新鲜度、使能、owner、SDK、工作进程、协议、速度、关节范围、2°余量和会话范围检查。
2. 确认无活动轨迹、moving=false、实测各轴速度不超过0.5°/s、命令与反馈差不超过原3°保持上限，夹爪没有待执行的目标变化。
3. 检查最近0.65秒内至少5个连续样本，覆盖至少0.5秒，末样本不旧于0.15秒、间隔不超过0.15秒；实测各轴变化不超过0.1°，最终关节目标已提交并保持，夹爪命令不变。
4. 锁存原任务故障，沿用已有 pause_hold，确认最多1秒内进入带电保持；另一臂必须已完成动作且健康静止，也锁住任务接口。
5. 保持独立相机、心跳和硬件监督。保持过程中要求目标不变、实测无超过0.1°的漂移、保持状态和原条件持续成立。任一失败回到原保护路径；丢失 owner 不向新 owner 下发命令。

夹爪卡滞、相机错误、心跳超时、通讯/硬件故障、活动轨迹和双臂同时运动不适用这条路径。进入保持不等于到位成功、不等于抓稳，也不证明无接触或碰撞。

## 故障后行为

保持宿主进入隔离循环，继续监督但不再读取并执行任务队列。禁止 renew、resume、回位、重试、开合夹爪和自动故障清除。原任务 guard 与预算保留，监视副本只检查原会话范围，不接受动作。

事件 `arrival_fault_hold` 保存原错误、两臂状态和失败反馈；`arrival_fault_hold_ended` 记录保持结束原因。原任务 `review_command_finished.outcome` 仍为 failed。录像是独立进程，不由这条故障处理路径停止。

这是软件容错，不是安全制动。`fault_fallback_hardware_validated` 仍为 false。停止进程、失去反馈/控制权、断电或通讯中断仍可能失能；不得以本改动代替可靠承托。
