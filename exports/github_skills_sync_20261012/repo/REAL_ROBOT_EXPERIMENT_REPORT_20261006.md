## 1. 背景、目标与本版可回答的问题

项目负责人为海宝。核心问题是：GPT-6 Astra等通用大模型在数字任务中的能力，能否迁移到需要准确接触、保持物体约束和持续调节作用力的物理任务。项目通过仿真和多种真实机械臂测试完成程度、失败边界、资源消耗与跨设备差异，产出测试报告及附件，为团队和行业提供可复查材料。

“接触精度、过程约束和持续力控仍有短板”是待检验判断，不是任务选择和评分的前提。当前失败来自模型、观测、控制接口、夹具/物料与设备状态共同构成的系统，现有材料不能把全部失败唯一归因于模型，也不能从少量成功推断普遍可靠。

| 项目问题 | 本版提供的证据 | 当前能得出的结论与缺口 |
| --- | --- | --- |
| 三层任务能完成到什么程度？ | 18类真机任务/变体的结果、阶段进展、约束与案例 | 能描述本机表现；正式任务表和层级映射缺失，尚不能给出L1/L2/L3统一成功数/总数 |
| 能力边界在哪里？ | 空抓、滑移、接触位置不当、插入不可确认、到位/链路故障的逐轮记录 | 可分解失败阶段；没有固定矩阵下的prompt、扰动或接口消融，不能确认因果增益 |
| 需要多少资源？ | 22个可取得的标准化资源窗口，含端到端耗时、token和去重response数 | 可核对已记录窗口；纯模型延迟、完整请求重试账、统一费用未取得，均不填0 |
| 结论能否跨设备成立？ | 当前报告仅ARX R5一种本体，双臂为同型号设备 | 尚不能支持跨设备结论；不能把两条R5臂当两种本体 |

## 3. 任务、接口与测试协议

### 3.1 三层框架及当前映射状态

| 层级 | 用户方案已给出的定义 | 本版处理 |
| --- | --- | --- |
| L1 | 任务相关Affordance与几何操作 | 保留历史记录中已明确的L1标签，不据物体名称新增项目编号 |
| L2 | L1＋稳定交互中的受力与运动调节 | 保留双臂拔笔帽等历史标签；项目候选表与逐项条件缺失，正式映射待复核 |
| L3 | L1＋L2＋变化接触下的持续联合调整 | 尚不能从现有材料形成已确认的L3任务覆盖及统一得分；不把擦板自动映射为L3擦桌 |

同一物体在容差、阻力和过程约束变化后可属于不同层级。方案中的“L2-07抽屉”“原L2-08移为L3-11擦桌子”等作为文本线索保存；未展开的资产图和任务卡不足以把本机抽屉、擦板等实验直接认定为同一标准任务。“仿真4×5/真机2×3”也只是未解释的原文，结合“当前不预设回合数和总工作量”，不据此生成实验分母。

已有18项索引与项目编号分开保存，见[待对齐任务表](analysis/real_robot_report_20261006/protocol_alignment.csv)。缺少的编号、分层和正式纳入状态保持未确认，不用成功结果反推分类。

### 3.2 历史记录、正式回合与评分

现有资料包含联调、准备恢复、监督实验、局部重试、人工重新摆放及协议变体。本版按历史事实汇总；**是否可纳入统一正式矩阵，需要逐轮审阅任务卡、模型/接口版本、预算和扰动条件。** 既不把所有记录自动升格为正式测试，也不事后把未成功轮次全部剔除为预实验。

评分分开记录：抓起或有效接触、物体目标完成、过程约束、释放后独立稳定、受控回位、结束后设备状态。用户验收、图像证据和人工辅助分别标注；局部重试不冒充新的独立样本；末端位移不等于物体位移；指令角度不等于退丝或旋入圈数。

原记录已有分母时保留其口径：叠杯用户结果4/5，完整监督流程核验1/5；粗记号笔入宽口杯4/6包含人工辅助。它们是历史子协议描述，不是在相同条件下与其他任务/设备可直接比较的策略成功率。全体正式成功数/总数及各层汇总暂不生成。

### 5.3 代表性案例

#### 5.3.1 叠杯与笔入宽口杯：分阶段核验的价值

叠杯第3轮完成左杯放置及左臂回位后，再执行右杯套叠、释放和右臂回位，避免两臂同时占据操作空间。笔入杯的可重复成功主要来自粗笔与宽口杯变体；总序号7有整轮无场景介入证据。两项共同说明：先验证抓稳、留出操作通道、释放后复查，比只追踪末端是否到达目标更能支持成功结论。

#### 5.3.2 橘瓣抓放：改变观察位后修正抓取深度

第1轮前3次局部抓取未成功。右腕换位后看到橘瓣位于有效夹面后方，调整前后深度和高度，第4次试提获得稳定随动，随后放回并完成双臂回位。该案例支持“视差用于解决抓点深度不确定”，不支持仅增加闭合量就能解决空抓。[证据记录](ORANGE_PICK_PLACE_EXPERIMENT_RECORD_20261005.md)

#### 5.3.3 擦拭与扫入：目标与人工预置需明确

擦黑板第3轮以人工预置硬质板擦为初态，按“有接触擦拭动作、不要求字迹擦除”的新标准通过。扫块第1轮同样使用人工预置扫帚，2/2蓝块进入簸箕并在撤刷后稳定。这些案例证明对应条件下的工具运输/操作，不等同从桌面自主获取工具或已验证清洁质量。

#### 5.3.4 本轮新增：夹爪边缘推蓝块入红色三角区

用户要求直接用爪边推动，不夹起方块。早期接触高度及前后位置不合适，部分动作没有产生有效位移；随后侧推将方块移到三角区边缘。用户指出尚未完全进入，系统保留未成功判断，撤开取得更清楚视图。改到后侧并先退开、再降低接触高度后，两段短推获得进一步位移。用户验收成功；空爪撤开后方块仍在区域内。

### 5.4 失败发生在哪个阶段

| 阶段 | 代表观察 | 评分处理 |
| --- | --- | --- |
| 接触前/未建立有效抓持 | 空抓空提、物体留在支撑、指尖从上方经过 | 记录几何接近进展，不计接触目标成功；仅凭图像不能精确标定首次接触时刻 |
| 接触建立或维持中 | 夹持滑移、对侧接触丢失、整瓶/支撑物随动 | 分别记录约束丢失、非目标物位移与局部修正，不能只看爪子到位 |

### 5.5 故障、过程约束与人工介入

本系列存在到位异常后失能下落、CAN/SDK无反馈、代理SIGTERM中断以及人工挪动后的保持丢失。它们不是同一种故障。部分任务结束且已保存回位证据后，设备又发生新异常，例如拔笔帽、擦板和扫块；这不覆盖此前已完成结果，也不允许把故障前的健康状态当成后续当前状态。

用户对承托/防坠处理提供过现场确认，但报告没有足够装置位置、承载试验曲线或独立测量材料，不将口头确认写成已完成工程认证。原始故障、人工介入和缺失录像均保留。人工摆放、松帽、预置工具或更改目标影响试验条件，应在未来固定协议重复试验中单独控制。

### 7.2 能支持与不能支持的结论

目前能支持：R5监督执行系统在部分宽容差操作及明确人工预置条件下有成功案例；接触前定位与有效抓持、接触后的约束维持、精密对准，以及设备/服务稳定性均影响结果。空爪到位、几何投影重合或发出旋转命令不足以证明物理目标完成。

目前不能支持：统一三层成绩、固定策略成功率、模型之间的优劣、prompt/扰动的因果影响、仿真到真机差距、跨至少3种本体成立的结论，以及人类示范/力信息已提升本系统表现。现有成功/失败应作为后续正式矩阵与独立探索的问题依据，不作为预设论点的证明。

### 7.5 交给独立探索线的问题

按方案由海宝、梓健负责human demonstration、力控相关上下文与主动接触式物理交互探索。以下仅交接证据与问题，不预设对照组数量、实验量、排期或性能提升指标，不计入上表测试报告的交付验收。

| 现有问题依据 | 可交接的探索问题 | 尚无的结论 |
| --- | --- | --- |
| 果冻/帽子/抽书等有效抓持不稳定，橘瓣换视角后修正深度成功 | 示范能否更明确给出抓点、夹面和接触顺序？ | 现有人工提示/摆放不是受控示范收益试验 |
| 旋盖对侧接触丢失、螺母滑移，缺少任务力/扭矩证据 | 何种力上下文能区分“未接触、滑移、阻力与卡住”？ | 未证明加力信息必然改善，也未量测所需力矩 |
| 插头/瓶口仅靠视觉难以确认轴线与进入状态 | 主动接触能否在约束内降低几何不确定性？ | 目前没有主动接触策略的成功率或消融结果 |
| 推蓝块修正接触侧/高度后出现真实位移 | 怎样将物体响应与下一次接触调整形成可复查证据？ | 当前是一轮监督案例，不是可泛化策略验证 |

这些问题为后续探索提供依据；探索是否取得提升不作为本测试报告发布的前提。

| --- | --- |

| 杯间倒珍珠 | 源杯倾倒到接收杯，受控放回与回位 |

| 扫蓝块入簸箕 | 左臂用扫帚把所有蓝块扫入簸箕 |
| 夹爪边缘推蓝块入红三角 | 左爪外缘推进一个蓝块，进入目标区即成功 |
