## 启动

```bash
cd /home/tuojing/arx_r5_control
./connect_can.sh
./start.sh --live
```

打开 http://127.0.0.1:8765 。服务已启动时只需刷新网页。

1. 点击 **连接机械臂**，阅读并确认初始化提示。**厂商 SDK 构造函数会使能电机并包含回零流程。** 初始化过程中网页暂停不能打断 SDK 构造函数，需保持工作区空旷并能够操作设备急停/电源。
2. 等待 CAN 接收计数、实际关节角度和模型出现，然后点击 **启用控制**。
3. 关节/末端模式控制六个轴。按住移动，松开停止；空格或 Esc 请求 SDK 保护模式。保护模式可能不保持姿态，不能替代物理急停。
4. 夹爪显示原始反馈，目标用 **0–5 SDK 原始单位**，不是毫米；`[` 闭合、`]` 张开。图中夹爪宽度只是原始值的归一化估计，不是已校准的毫米开口。
5. 结束前点击 **断开**。原厂初始化期间不要直接关闭服务来尝试急停。

键盘默认启用：1–6 选轴，↑/↓ 点动；末端模式 W/S、A/D、R/F 为 XYZ，I/K、J/L、U/O 为三个旋转轴。输入框获得焦点时不会触发点动。

`connect_can.sh` 使用序列号固定路径，避免 ttyACM0/ttyACM1 变化。缺失 can0 时连接界面会提示重新运行它。实机日志在 `robot.log`。

## 双路相机实时预览

打开工作台 `http://127.0.0.1:8765` 后，主页面自动显示左臂 Gemini 305 和外接全局 RGB 相机，无需另开预览服务或授予浏览器摄像头权限。左腕使用 848×480、15 fps 原生 MJPEG，兼容当前 USB 2.0 连接；全局相机使用 640×480、30 fps。左腕固定匹配序列号 `CV2C8610015R`，不依赖易变的 `/dev/videoN` 编号；该相机缺失时会报错，不会自动换用右腕相机或笔记本摄像头。

未开启示范录制时，画面只在本机内存中转发，不上传、不录制，也不包含深度图。每路可单独暂停；没有其他预览或录制使用相机时，页面隐藏或关闭约 4 秒后释放设备，返回页面时自动恢复。设备被占用、断开或重新接入时，页面会显示错误并持续重试。`camera_preview.py` 仍可作为 Gemini 单路独立诊断工具使用，但不要和工作台同时预览同一台相机。

## 遥操示范录制与分析

在原控制服务 8765 已运行时，另开终端：

```bash
cd /home/tuojing/arx_r5_control
python3 record_workbench.py
```

打开 **http://127.0.0.1:8768**。该页面转发到现有控制服务，不重新创建 SDK、不重连或回零。录示范时请在 **8768 页面**完成全部操作：8765 或其他程序发出的命令无法被录制服务直接记录，但实机状态变化仍会被采样。

1. 在双路画面下方填写示范名称，点击「开始录制」，确认状态变成「录制中」。
2. 按原方式启用控制、遥操机械臂；可选标记「靠近」「夹取」「抬起」「放下 / 松开」或填写备注。
3. 完成动作后使用原控制区的暂停按钮。选择本次结果，再点击「停止并保存」。录制按钮本身不启用、不移动、不暂停机械臂。
4. 展开「已保存的示范与动作分析」，查看六关节范围、夹爪反馈范围、阶段时间和数据质量，或下载 TAR 数据包。

录制目标频率为状态 20 Hz、每路相机 10 Hz。Gemini 是腕部视角，外接 RGB 是第三人称视角。图像时间戳为本机接收时间，不是相机曝光时间；两路相机非硬件同步。状态包含原反馈新鲜度字段，不能把轮询时间当成关节独立采样时间。末端姿态来自现有 URDF FK，未经实际 TCP 标定。记录目标、下发角度和实测角度分别保存。

文件保存在 `recordings/<示范编号>/`：

- `manifest.json`：任务名称、人工结果、模式、时间、单位、统计和采集错误计数。
- `timeline.jsonl`：状态、经过录制页面的控制命令（含接收时间、接受/拒绝/结果未知）、阶段标记、图片索引、采集错误。分析时按 `t_ns` 排序，所有时间相对于本段示范开始。
- `gemini/*.jpg`、`external/*.jpg`：两路 RGB 原始 JPEG 帧，不含深度。

录制在后台继续，即使关闭/隐藏页面或暂停单路预览也不会停止。每段上限 15 分钟或约 2 GB；磁盘余量不足 512 MB、写盘失败或队列过载时停止采集并标记异常，不改变机械臂控制。相机短暂断开会记录错误并重试。服务异常退出后保留已有文件，历史记录将未完成段标记为 interrupted。正常退出录制服务会尝试保存当前段。

数据与统计供后续示范分析使用，不自动训练模型、不自动复现运动，也不能仅凭关节运动判断抓取成功。成功/失败结果由操作者标注。

验证：`python3 -m unittest discover -s tests -v`。`tests/browser_recording.cjs` 是只采集、不运动的浏览器验证；运行需要本机 geckodriver 4444 和闲置、未录制的 8768 工作台，测试会保存一段明确命名的静止验证记录。

## 逐步看图控制接口

`visual_control.py` 提供读取双路画面和实机状态、输出绝对关节/夹爪目标、执行有限小步的接口。它不需要相机内外参，但也不把像素转换成毫米位置。球检测为颜色和轮廓候选，不负责判断障碍物、线缆张力、接触或抓取成功。

只读观察（不会启用机械臂）：

```bash
python3 visual_control.py observe
```

输出包括六关节角度、夹爪 SDK 原始反馈、目标值、相机分辨率/设备/帧编号、球候选像素中心和图像文件路径。未取得的相机内外参明确为 null。

`python3 visual_control.py session` 启动由操作者或看图代理监督的交互会话。每行输入 JSON，支持 `{"action":"observe"}`、`{"action":"step","joints_deg":[六个绝对角度],"gripper_raw":原始目标}` 和 `{"action":"stop"}`。后两个目标字段可选；目标必须从最新反馈计算，不能将示例占位符直接发送给设备。

首个有效 step 才启用控制。速度固定为 10%，单关节每步最多 2°、合成步长不超过 3°，夹爪目标每步最多改变 0.1 SDK 单位；关节与夹爪必须分步请求。会话还有累计位移和步数预算，重新观察不会清空预算。每步留出 5 秒执行窗口；运动关节未在窗口内接近目标时请求原有保护模式。两路画面断流、反馈超时、SDK 错误、控制权/速度变化、跟随限幅或 30 秒没有新的监督观察/动作都会中止会话。用户网页暂停后不会自动重新启用。

新增软件检查详见 [SOFTWARE_MOTION_GUARDS.md](docs/SOFTWARE_MOTION_GUARDS.md)。这些限制不是防坠、碰撞检测或已验证的物理停止方案；现有保护模式可能下垂的问题尚未解决。GPT-Policy 仍为只读/影子模式，旧视觉执行入口也不能作为绕过实机验证的办法。本次改动没有启动实机运动；网页手动控制没有自动套用这些新限制。

窗口结束时，关节到位判断要求：所有关节目标残差不超过 1°、请求变化超过 0.1° 的关节沿目标方向完成至少 70% 位移，以及连续至少 0.5 秒所有关节峰峰值不超过 0.1°；反馈样本间隔不得超过 0.15 秒。这是小步观察的完成条件，不是碰撞检测或抓取成功判据。SDK 保护模式实测可能让姿态回落，不等同于保持当前位置。

也可使用 `{"action":"step","joint_delta_deg":[0,0,4,0,0,0]}`，相对步长在执行时根据新鲜反馈生成绝对目标，避免照抄较早观察中的其他关节角度。不能与 `joints_deg` 同时使用；所有步长和到位保护仍然适用。动作日志保存计算目标时的初始角度。

会话持续发送心跳，步骤之间保持已下发目标，等待监督者查看新画面再决定下一步。没有正在录制的示范时会自动创建记录；已有录制则复用，不负责停止操作者原有的录制。会话退出会请求现有 SDK 保护模式，它可能不保持负载，不能视为物理急停或稳固持球模式。

### 暂停保持原型（仅离线验证）

控制器新增 `pause_hold` / `resume`：取消旧动作、按规划速度减速、锁定一次保持目标，明确恢复后才接受新动作，不自动续跑原轨迹。保持期间仍为使能状态，必须持续发送零点动心跳；`stop`、失联和故障仍走原有保护路径。

模拟 API 已支持该功能；实机默认 `hold_available=false`，网页没有开放开关。本次没有重启实机服务，也没有把视觉超时或网页暂停自动改为保持。**SDK 保护模式和断电后的回落问题尚未获得硬件验证，不能把本功能当成急停或抱闸。** 状态、测试方式和实机验收前提见 [暂停保持说明](docs/PAUSE_HOLD.md)。

此接口是逐步看图控制的执行工具，尚不是经过实机验证的一键自动抓取算法；不会自行选择接近路径或把历史轨迹整段重放。使用前需确认实体工作区及线缆余量。当前已完成只读相机/状态验证及软件边界测试，尚未用此新会话执行完整实机抓取。
